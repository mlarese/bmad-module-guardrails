# Intento di ricerca e architettura informativa

## Risultato

Una mappa che collega obiettivo commerciale, pubblico, domanda di ricerca, intento, tipo di pagina,
URL canonica, contenuto e link interni. Il consumatore è chi deve decidere quali pagine creare,
unire, aggiornare o non pubblicare.

## Metodo di ragionamento

Non partire da una lista di keyword. Parti da:

- problema che l'utente vuole risolvere e azione che il progetto considera valore;
- mercato, lingua, località, dispositivo, fase del percorso e vincoli di prodotto;
- evidenza disponibile: query Search Console, interviste, ricerca sul sito, SERP osservata, supporto,
  vendite o ipotesi esplicita;
- tipo di intento: informarsi, confrontare, scegliere, acquistare, navigare verso un'entità;
- pagina che può soddisfare quell'intento meglio di una pagina generica.

Per ogni cluster scrivi una sola promessa di pagina. Se due pagine hanno stesso intento, pubblico e
prova, non moltiplicarle solo per variare la keyword: valuta consolidamento, differenziazione reale
oppure una sola pagina canonica.

## Mappa utile

| Campo | Domanda |
| --- | --- |
| Domanda | Quale bisogno espresso o implicito stiamo osservando? |
| Intento | Che cosa vuole poter fare o sapere la persona dopo la pagina? |
| Evidenza | Da dove proviene la domanda e quanto è affidabile? |
| Pagina | Quale contenuto completo risponde senza rinvii inutili? |
| URL | È descrittiva, stabile, unica e coerente con la gerarchia? |
| Linking | Quali pagine la scoprono e quali pagine aiuta a scoprire? |
| Conversione | Qual è l'azione coerente con questo intento? |
| Verifica | Quale segnale mostrerebbe che l'ipotesi funziona? |

## Difetti ricorrenti

- categorie e filtri che creano migliaia di URL senza domanda o contenuto distinto;
- blog usato per intercettare query lontane dall'offerta, senza percorso utile verso il prodotto;
- pagine quasi uguali per ogni città, settore o variante, con località sostituite a testo invariato;
- navigazione visiva senza link crawlable o link interni con anchor generiche;
- gerarchia del menu che rispecchia l'organigramma interno invece di quello che serve agli utenti;
- contenuti cannibalizzati per la stessa intenzione e pagine orfane che nessun percorso raggiunge.

## Vincolo

La keyword è una traccia linguistica, non il prodotto. Non prescrivere densità, numero di occorrenze
o un conteggio magico di pagine. Se mancano dati, proponi un'ipotesi dichiarata e un modo economico
per falsificarla.
