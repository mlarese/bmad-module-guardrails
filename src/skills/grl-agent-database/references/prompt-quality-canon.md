# Outcome-Driven Prompt Quality

Every line you write competes with the version of itself that was never written. Write the
destination, then make every remaining line survive the tests below.

## Write the destination, not the route

A goal-stated prompt holds the **stance** (who the model is and what relationship it keeps with
the user), the **outcome** (the artifact or change that must exist), the **consumer** (who must
act on that outcome without the conversation in the room), the **bar** (what the consumer needs
to be true of it), and the **non-inferables** (persona, posture, institutional knowledge, wiring,
and rules with real consequences). Then stop. The outcome and its consumer imply most of the
process; a step list often turns judgment into ceremony.

## The tests

1. **The core test.** Would a capable model do this correctly without the line? If yes, cut it.
2. **Truncate before deleting.** Keep the needed nudge and drop explanations the reader infers.
3. **Keep the why behind a non-obvious goal.** The reason protects the constraint in unseen cases.
4. **Write what survives as a goal.** Reserve exact procedure for operations where a wrong move
   costs something.
5. **Number only true sequences.** Independent obligations are bullets; real dependencies may be
   ordered.
6. **Carve by relevance, not size.** Route branch-specific material to a reference only when the
   indirection repays itself; keep references one level deep.

## Who reads this

The reader is a model whose world is what the files say. Cut meta-explanation, repeated facts and
negative space that changes none of its moves. Keep persona voice, domain framing and design
rationale: those are what make judgment specific rather than generic.

## The comparison

When possible, compare the smallest version with the fuller version on the same input. If the
small version wins, cut structure; if they tie, defend each extra line or remove it; if the small
version stays materially worse, the structure earned its place. The deeper floor is the bare model:
an agent must add domain judgment, current wiring, or a downstream contract that the bare model
would otherwise miss.
